# Open-Source Preparation — GSoC 2027

A practical workspace for learning open-source contribution workflows and preparing for GSoC 2027.

> This repository is a learning log, not a portfolio of claimed contributions. Record only work you actually completed.

## Goals

- Learn Git and GitHub collaboration workflows.
- Set up and understand at least one real open-source codebase.
- Submit small, meaningful contributions and respond to maintainer review.
- Build enough project understanding to evaluate a GSoC idea and write an original proposal.

## Current focus

Start with **one repository at a time**. Based on my current React/Node/TypeScript experience, candidate projects are:

1. [Zulip](https://github.com/zulip/zulip)
2. [Rocket.Chat](https://github.com/RocketChat/Rocket.Chat)
3. [Oppia](https://github.com/oppia/oppia)

These are exploration candidates, not confirmation that they will participate in GSoC 2027. Check each project's current contribution guidance and GSoC status before investing heavily.

## Repository map

- `checklists/` — weekly setup and contribution checklists
- `learning-notes/` — Git, codebase, testing, and debugging notes
- `issues/` — issue investigation notes
- `pull-requests/` — PR log and review learnings
- `templates/` — reusable issue and PR investigation templates
- `proposal/` — notes for an original proposal; follow the target organization's AI/authorship policy

## Working rules

1. Read the project's contribution guide before opening an issue or PR.
2. Reproduce a bug before attempting to fix it.
3. Keep changes focused and add/update tests where appropriate.
4. Never claim an issue, PR, or contribution that you did not complete.
5. Follow the project's AI policy. If AI assistance is restricted, do not use it for restricted work. Write any GSoC proposal in your own words and disclose assistance when required.
6. Be respectful, patient, and responsive to maintainer feedback.
